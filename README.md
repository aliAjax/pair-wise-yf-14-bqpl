# hxyfront-62002 剧场灯光Cue表管理

源提示词编号：2

给剧场灯光师使用的灯位与 Cue 表管理前端，支持排练期间推进每条 Cue 的执行状态。

## 排练演出版规则

- **灯具焦点（全局维护，不分版本）**：每盏灯有「待确认 / 已确认」焦点状态。在灯位图或灯具表确认后，关联 Cue 才会进入「待触发」；撤销焦点会立刻把关联 Cue 打回「不可触发」。
- **Cue 依赖（全局资料）**：维护 Cue 的触发顺序号、关联灯具、通道号（取自灯具）、色片、亮度预设和资料备注。
- **触发闸门**（每次操作实时推导）：
  - 关联灯具焦点未全部确认，或灯具缺失 → 不可触发；
  - 触发顺序中紧邻的上一条 Cue 未完成 → 后一条不可触发；
  - 通道号正被其他「已触发未完成」的 Cue 占用（撞车）→ 不可触发，卡片会给出具体 CH 与占用方；
  - 两条 Cue 的预设通道存在静态交集时，两侧长期显示「通道撞车」警示（演示数据中 BK-03 / BK-05 同占 CH 43，Cue 24 与 Cue 30 互相标红）。
- **Cue 生命周期**：不可触发 → 待触发 → 已触发（通道占用、灯位图点亮）→ 已完成（放行后一条）；可单条复位，也可整版复位（保留备注）。
- **版本进度独立**：每个演出版本只保存自己的触发进度、每条 Cue 的排练备注和版本备注；切换/切回旧版本时，原来的进度与备注原样恢复。可新建版本并选择是否复制当前版本进度。
- **状态可视化**：舞台平面灯位图（焦点状态、点亮光束、撞车角标、灯具筛选）和 Cue 列表（状态徽标、拦截原因、进度条）都显示实时状态；顶部指标汇总待确认灯具、待触发 Cue、当前场景与通道告警。

灯具 / Cue 的增删改在「灯具焦点」「Cue 依赖」两个页签完成；全部资料保存在浏览器 localStorage，可用「恢复演示数据」重置。

## 技术栈

React 19 + Vite 7 + TypeScript（严格模式），无额外运行时依赖。

## 本地运行

```bash
npm install
npm run dev
```
